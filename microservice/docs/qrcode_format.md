# 藥袋二維碼資料格式

> 本文件整理「藥報平安」藥單範本所需的資料，說明藥袋二維碼（QR Code）要放哪些內容，掃描後才能直接建立藥單。
> 對應程式：`microservice/frontend/src/utils/qr.ts`（`parsePrescriptionQr`）

## 一、二維碼內容規則

二維碼內容支援兩種：

1. **藥單 JSON**（建議）：二維碼內容直接是一段 JSON 文字（UTF-8，格式見第二節），掃描後直接建立藥單。須用「**靜態**」二維碼產生。
2. **藥單圖片網址**：二維碼內容是 `http(s)://` 開頭的網址，指向一張藥單圖片（現行許多藥袋的做法）。掃描後由後端下載圖片、做文字辨識（OCR），整理成第二節的格式（API 見第六節）。

流程：

```
掃描二維碼 ─┬─ 藥單 JSON ──────────────────────────────┐
            ├─ 網址 → 後端下載圖片 → OCR → 整理成藥單 ─┼→ 確認藥單（人工逐項核對）→ 加入藥單
            └─ 其他內容 → 掃描失敗                       │
                    任一步驟失敗 → 掃描失敗：{錯誤原因} ←┘
```

- 掃到不符合格式的內容或任一步驟失敗時，畫面顯示「**掃描失敗**」與**錯誤原因**，並列出讀到的內容。
- OCR 可能讀錯，整理後的藥單一律進入「確認藥單」由藥師或家人逐項核對後才加入。

## 二、藥單範本需要的資料

### 藥單（整張）

| 欄位 | 中文 | 必填 | 格式／範例 | 用在哪裡 | 沒填時 |
| --- | --- | --- | --- | --- | --- |
| `hospital` | 醫院／院區 | ✔ | `"仁愛院區"` | 藥單標頭、回診預約自動帶入院區 | 掃描失敗 |
| `department` | 科別 | | `"心臟科"` | 藥單標頭、回診預約自動帶入科別 | 只顯示院區 |
| `visitDate` | 看診（領藥）日 | | `"2026-11-08"`、`"2026/11/08"` 或民國 `"115.11.08"` | 從這天開始算還剩幾天 | 今天 |
| `days` | 給藥天數 | | `28` | 藥品沒有 `quantity` 時，用來推算總顆數 | 28 |
| `medicines` | 藥品清單 | ✔ | 陣列，至少 1 筆（見下表） | 藥品核對卡、時段、提醒 | 掃描失敗 |

> 藥單代碼（A、B、C…）與藥品代碼（A1、A2…）由 App 自動編號，不需放在二維碼裡。

### 藥品（`medicines` 每一筆）

| 欄位 | 中文 | 必填 | 格式／範例 | 用在哪裡 | 沒填時 |
| --- | --- | --- | --- | --- | --- |
| `name` | 藥名＋劑量 | ✔ | `"Aspirin 100 毫克"` | 藥品卡、朗讀、緊急醫療卡目前用藥 | 掃描失敗 |
| `amount` | 一次幾顆 | | `1`、`0.5`（以半顆為單位） | 顆數、每天吃幾顆 | 1 |
| `slots` | 什麼時候吃 | | `["早上","晚上"]`（早上／中午／晚上／睡前） | 四個時段、吃藥提醒（9:00／12:00／18:00／22:00） | 依 `frequency`，再沒有則早上 |
| `frequency` | 頻率代碼 | | `"TID"`（見下方對照表） | 沒有 `slots` 時換算成時段 | — |
| `meal` | 飯前／飯後 | | `"飯前"` 或 `"飯後"` | 藥品卡、朗讀 | 飯後 |
| `effect` | 功效 | | `"預防血栓"` | 藥品卡、朗讀、緊急醫療卡 | 空白 |
| `quantity` | 總顆數 | | `28` | **還剩幾天 = 剩下顆數 ÷ 每天吃幾顆** | `days` × 每天吃幾顆 |

### 頻率代碼 → 時段對照

| 代碼 | 意思 | 換算的時段 |
| --- | --- | --- |
| `QD`、`QAM` | 每天一次（早上） | 早上 |
| `QPM` | 每天晚上一次 | 晚上 |
| `HS`、`QN` | 睡前 | 睡前 |
| `BID`、`Q12H` | 每天兩次／每 12 小時 | 早上、晚上 |
| `TID`、`Q8H` | 每天三次／每 8 小時 | 早上、中午、晚上 |
| `QID`、`Q6H` | 每天四次／每 6 小時 | 早上、中午、晚上、睡前 |

> 同時有 `slots` 與 `frequency` 時以 `slots` 為準。

## 三、範例

### 最少必要資料

```json
{"hospital":"仁愛院區","medicines":[{"name":"Aspirin 100 毫克"}]}
```

→ 今天看診、早上吃 1 顆、飯後、28 顆。

### 完整資料

```json
{
  "hospital": "仁愛院區",
  "department": "心臟科",
  "visitDate": "2026-11-08",
  "days": 28,
  "medicines": [
    { "name": "Amlodipine 5 毫克", "amount": 1, "slots": ["早上"], "meal": "飯後", "effect": "降血壓", "quantity": 28 },
    { "name": "Metformin 500 毫克", "amount": 1, "frequency": "BID", "meal": "飯後", "effect": "降血糖", "quantity": 56 }
  ]
}
```

## 四、與現行藥袋「藥單內容」的對照

以使用者測試的藥袋二維碼為例：該二維碼內容是一張藥單圖片的網址（`scqa_drug_warning02.jpg`），圖片上的資料可對應如下。若要能直接掃描建立藥單，需請醫院把這些資料以上方 JSON 格式放進二維碼（或由後端讀取圖片後轉成此格式）。

| 藥單圖片上的欄位 | 範例 | 對應欄位 |
| --- | --- | --- |
| 醫院名稱 | 醫聖模範診所 | `hospital` |
| 科別 | 01 | `department` |
| 就診日 | 107.10.10 | `visitDate`：`"107.10.10"`（民國年可直接使用） |
| 藥品名稱及劑量 | Dl-methylephedrine | `medicines[].name` |
| 途徑 | 內服 | （目前未使用） |
| 數量（一次用量） | 1 | `medicines[].amount` |
| 服用方法 | 每八小時使用一次 | `medicines[].frequency`：`"Q8H"` → 早上、中午、晚上 |
| 總量 | 9.0 TB | `medicines[].quantity`：`9` |
| 天數 | 3 天 | `days`：`3` |
| 適應症 | 支氣管氣喘、蕁麻疹、過敏性疾病 | `medicines[].effect` |
| 副作用、警語 | 心悸、頭痛…／請勿開車 | （目前未使用，未來可加入藥品詳情） |
| 姓名、身分證、費用 | 金富貴、A88888****、50 元 | （藥單範本不需要；姓名與身分證屬個資，不建議放進二維碼） |

對應後的二維碼內容：

```json
{"hospital":"醫聖模範診所","department":"01","visitDate":"107.10.10","days":3,
 "medicines":[{"name":"Dl-methylephedrine","amount":1,"frequency":"Q8H","effect":"支氣管氣喘、蕁麻疹、過敏性疾病","quantity":9}]}
```

## 五、掃描失敗的情況

| 情況 | 畫面提示 |
| --- | --- |
| 內容不是 JSON 也不是網址（例如一般文字） | 掃描失敗：這不是藥袋的二維碼，並列出讀到的內容 |
| 內容是網址，但無法讀取藥單 | 掃描失敗：{錯誤原因}（見第六節錯誤代碼對照） |
| 是 JSON 但缺少必填欄位 | 掃描失敗：藥單資料不完整，缺少：院區（hospital）／藥品清單（medicines）／藥名（medicines[].name） |
| 照片裡找不到二維碼 | 掃描失敗：這張照片裡找不到二維碼 |
| 相機 20 秒內沒掃到 | 掃描失敗：找不到二維碼，請靠近一點或改用上傳照片 |
| 瀏覽器不支援相機掃描 | 掃描失敗：請改用「上傳 QR Code 照片」 |
| App 掃描器沒有回傳結果 | 掃描失敗：沒有掃到二維碼 |

## 六、網址型二維碼：藥單辨識 API（後端）

前端無法直接處理網址中的圖片（瀏覽器跨網域限制，OCR 也需在伺服器執行），需由後端提供以下 API。
前端程式：`microservice/frontend/src/services/prescriptionOcr.ts`；後端位址設定於前端 `.env.local` 的 `VITE_API_BASE_URL`（未設定時，網址型二維碼一律顯示「無法連線到藥單辨識服務」）。

### 請求

```
POST {VITE_API_BASE_URL}/api/prescriptions/ocr
Content-Type: application/json

{ "imageUrl": "https://www.sc-dr.com.tw/shangchan/upload/images/scqa_drug_warning02.jpg" }
```

### 成功回應（HTTP 200）

`prescription` 格式與第二節相同：

```json
{
  "prescription": {
    "hospital": "醫聖模範診所",
    "department": "01",
    "visitDate": "107.10.10",
    "days": 3,
    "medicines": [
      { "name": "Dl-methylephedrine", "amount": 1, "frequency": "Q8H", "effect": "支氣管氣喘、蕁麻疹、過敏性疾病", "quantity": 9 }
    ]
  }
}
```

### 失敗回應（HTTP 4xx／5xx）

```json
{ "error": { "code": "URL_NOT_FOUND", "message": "網址打不開（找不到這個網頁或圖片）" } }
```

### 錯誤代碼對照（畫面顯示「掃描失敗：{錯誤原因}」）

| 代碼 | 情況 | 畫面顯示的錯誤原因 |
| --- | --- | --- |
| `INVALID_URL` | 網址格式不正確 | 二維碼裡的網址格式不正確 |
| `URL_NOT_FOUND` | 網址 404、網域不存在 | 網址打不開（找不到這個網頁或圖片） |
| `URL_FORBIDDEN` | 網址 401／403 | 網址打不開（網站拒絕存取） |
| `DOWNLOAD_FAILED` | 連線失敗、其他下載錯誤 | 網址打不開（圖片下載失敗） |
| `NOT_IMAGE` | 網址內容不是圖片 | 網址的內容不是藥單圖片 |
| `IMAGE_TOO_LARGE` | 圖片超過大小上限 | 藥單圖片太大，無法讀取 |
| `OCR_FAILED` | 圖片讀不出文字 | 藥單圖片上的字讀不出來 |
| `NOT_PRESCRIPTION` | 有文字但找不到藥名／用法／數量 | 圖片上找不到藥單資料（藥名、用法、數量） |
| `TIMEOUT` | 處理逾時（前端等待上限 30 秒） | 讀取藥單逾時 |
| （前端）無法連線 | 後端未設定或連不上 | 無法連線到藥單辨識服務 |
| 其他代碼 | — | 使用後端回傳的 `message` |

### 後端處理建議

1. 只允許 `http`／`https`，並限制可下載的網域與檔案大小，避免被用來存取內網資源（SSRF）。
2. 下載圖片後做 OCR，從文字中擷取第二節的欄位（醫院、就診日、藥名、用量、服用方法 → `frequency`、總量 → `quantity`、天數 → `days`、適應症 → `effect`）。
3. 圖片上的姓名、身分證、費用等個資不回傳、不保存；處理完即刪除圖片。
